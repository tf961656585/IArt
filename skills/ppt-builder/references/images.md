# 图片：三类图片、两步生图、图片质检

> 什么时候读：大纲里有图、要写 `deck.image / illustration / mood`、或处理 image_requests.json 时。
> 组件库**不调用任何生图接口**：它只生成 prompt、接收你生成的文件、负责裁切/圆角/标签/质检。图片由你用自己的生图能力生成。

## 1. 三类图片
| 类型 | 创建 | 来源 | 用在哪里 | 系统自动 |
|---|---|---|---|---|
| 本地图片 | `deck.image(path, source="", ratio=None)` | 调用方/用户自备（截图、照片、图表、设计稿） | `Evidence(image=...)` | 等比放入不裁切、不重绘；圆角+边框；图下"本地图片 <source>"；可加标注 |
| 插图 | `deck.illustration(subject, ratio="4:3")` | 你的生图能力 | `Evidence(image=...)` | 居中裁切到比例；圆角+边框；图下"插图（AI生成，仅辅助理解）" |
| 氛围图 | `deck.mood(subject, ratio="3:4")` | 你的生图能力 | `cover(image=)`、`section(image=)`、`slide(decor=)` | 裁切铺满；章节页自动加主题色遮罩，白字对比度 ≥4.5:1 |

比例只能是 `16:9` / `4:3` / `1:1` / `3:4`。插图一般 4:3；氛围图用默认 3:4（封面右栏、章节左栏、互动页窄栏都是竖版）。

## 2. 选哪一类（按顺序判断）
1. **要求准确的内容**——数字、图表、数据可视化、结构标注、尺寸、需要精确的示意——**只能用本地图片或组件**（Table / Steps / Compare / Example），**不要用 AI 图**。AI 画不准，且画错了没人能一眼看出来。
2. 材料里有现成图片 → 本地图片。用户还没给 → 先问用户要；暂时没有就用 `Evidence(placeholder="要放的图：xxx")`，并在交付报告里列出。
3. 只为帮听众"看到场景、理解概念"，且没有现成图（如"值班室整体环境"）→ 插图。插图不承载知识细节，讲解写在标题和 notes。
4. 氛围图只做装饰：封面 1 张；章节页可以共用 1 张；互动页 decor 全套最多 3 页。讲内容的页面不放。
5. 每页最多 1 张图；两张图左右对比的页面可以放 2 张（两个 Evidence 同页，不能上下排）。

## 3. 怎么写 subject（画面描述）
- 一句话：主体 + 场景 + 动作/状态，4–60 字。例："运维人员站在两排机柜之间查看监控大屏"。
- **只写画面内容**。风格（主题配色扁平插画）、"不得出现文字"、禁止项、比例都由组件库自动拼进完整 prompt，不要自己写。
- 不要要求图里出现任何文字；需要文字就用标题、图注、标注（在图外）。
- 同样的 subject + ratio + 主题 → 同一个 id 和文件名；改了 subject 就会产生新的请求。

## 4. 两步生图流程
1. 写好 build.py 后**第 1 次运行**。AI 图还不存在，页面上显示占位框（写着请求 id），质检报告"必须修复"里会有"图片尚未生成"。pptx 同目录生成 `image_requests.json`：
```json
{"requests": [{
  "id": "ill_6d6ee7", "kind": "插图", "ratio": "4:3", "size": "1600x1200",
  "filename": "images/ill_6d6ee7.png", "abs_filename": "/…/images/ill_6d6ee7.png",
  "status": "待生成", "pages": [5], "subject": "……",
  "prompt": "（完整 prompt：画面 + 风格 + 禁止项 + 英文版）", "negative": "text, letters, …"}]}
```
2. 对每条 `status` 为"待生成"的请求：
   - 把 `prompt` **原样**交给你的生图能力；支持反向提示词就填 `negative`；
   - 尺寸用 `size`（至少比例要等于 `ratio`）；
   - 保存为 PNG，路径**完全等于** `abs_filename`（不要改名、不要换目录）。
3. **第 2 次运行** build.py（在同一个工作目录运行）。已有图片会被自动处理并放入；质检报告列出剩余问题。
4. 需要重新生成的图：先删除旧文件，再按第 2 步生成，再重跑。
5. 你的环境没有生图能力：跳过第 2 步，保留占位框，把 image_requests.json 交给用户，在交付报告中注明；也可以用 `Evidence(placeholder=...)` 换成"待补图"的干净占位。

## 5. 图片质检
**规则层（组件库自动，出现在质检报告里）**
| 检查 | 级别 | 怎么修 |
|---|---|---|
| 文件不存在（AI 图未生成 / 本地图片缺失） | 必须修复 | 按 image_requests.json 生成；本地图片向用户要或换文件路径 |
| 分辨率 < 每 pt 1.5 像素 | 建议修复 | 按 `size` 重新生成，或换更清晰的图 |
| 源图比例不符，需裁掉 >25% | 建议修复 | 按 `ratio` 重新生成（只针对 AI 图；本地图片是等比放入不裁切） |
| 本地图片 source 超过 40 字 / 本页来源标注超过 60 字 | 报错停止 | 精简来源标注，详细出处写进讲者备注 |
| 路径字符串直接传给 Evidence / 氛围图当证据 / 插图当氛围图 | 报错停止 | 按报错提示改用对应方法 |
| 内容页加 decor / decor 超过 3 页 / 一页超过 1 张图 | 报错停止 | 去掉多余图片 |
| 创建了图片但没放到任何页面 | 建议修复 | 删除这次创建或放进页面 |

**视觉层（你必须自己看图）**：每张 AI 图生成后打开查看，任一项不通过就重新生成（同一张最多 3 次；仍不行改用 placeholder，并在 notes 写"【需人工检查】原因：……"）：
- [ ] 画面里有没有文字、字母、数字、乱码、假文字（招牌、屏幕、标签上的也算）？
- [ ] 是否出现了不该由 AI 画的准确内容（数字、图表、结构标注、需要精确的示意）？有就改 subject 去掉相关元素，或改用本地图片。
- [ ] 主体是否清楚、后排能看懂？是否和本页标题说的是同一件事？
- [ ] 风格、配色和其他图是否一致？
- [ ] 本地图片：清晰、完整、关键部分没被截掉？来源标注对不对？标注点是否落在正确部位？

## 6. 文件与目录
- `images/`（可用 `Deck(..., image_dir=...)` 改）：AI 图存放处。相对路径按**运行 build.py 时的当前目录**计算，所以每次都在同一目录运行。
- `images/_processed/`：组件库处理后的中间图，每次 save() 自动清理没用到的旧文件，不要手动放东西进去。
- 本地图片建议放在工作目录的 `assets/`，用 `deck.image("assets/console.png", source="设计稿 v2")` 引用；也可以放任何路径。
